## ProPrj_立创·黄山派SF32LB52开发板 .epro2 解析（可复用）

- `.epro2` = **zip**：内含 `project2.json`（工程元信息）+ `xxx.epru`（真数据）+ `IMAGE/`。
- `.epru` **不是 SQLite**，是**逐行记录**的文本流：每行 `{header}||{body}|`，`header.type` 为 DOCHEAD/CANVAS/COMPONENT/WIRE/LINE/TEXT/PIN/ATTR/PART/POLY/RECT…，
  DOCHEAD 的 **body** 里才带 `docType`（SCH / SCH_PAGE / PCB / SYMBOL / DEVICE / FOOTPRINT / BOARD / BLOB…）。按 DOCHEAD 切分得 219 个文档。
- 该工程：2 个原理图 —— `黄山派LCD屏幕板_SCH_V1.1`（1 页 P1）、`黄山派核心板_SCH_V1.2`（8 页 + 简介页）；2 块 PCB。
- 关键解析规则：
  - COMPONENT 只有 x/y/rotation/isMirror/partId，图形来自 `ATTR key=Symbol` 指向的 SYMBOL 文档；
  - SYMBOL 文档里 PART.BBOX 给包围盒，RECT/LINE/POLY(用 path 数组，数字对+命令字母)/PIN(x,y,length,rotation) 给图形；
  - WIRE 本身无坐标，几何在 `LINE` 里、用 `lineGroup == WIRE 的 id` 关联；
  - 器件位号/名称在 SCH_PAGE 的 `ATTR key=Designator/Name`（parentId 指向 COMPONENT id）；
  - 图框器件靠 ATTR 里有 `Page Size`/`Border` 识别，渲染时要剔除，否则画布被撑爆。
- 渲染脚本：`C:/Users/1/Downloads/_hs/render_sch.py`（PIL 直出 PNG，输出到 `_hs/pages/`）。

## 黄山派核心板 电源网络结论（VSYS_S / VSYS）

- 板上**没有** DC-DC 或负载开关做 VSYS_S→VSYS；两者唯一交点是 **CN3（XDZ127-2-15，30P）第 7、8 脚**，靠**插跳线帽**导通。原图注释（POWER 页，坐标 510,-470）："过30p接插件跳线帽和VSYS相连"。
- 完整链路（U3=SY6103 充电/BMS）：USB→OVP(U17 SY5320)→VBUS_5V→U3.A1；U3.A2=**VSYS_S**（只挂 C6、CN3.7）；跳线→**VSYS**→板上 LDO U2(LP5240HVF)/U19 输入。
- 同类模式：电池 CN1→**VBAT_S**→CN3 5/6 跳线→**VBAT**→U3.A3；U4(ETA5055) 输出 **VCC_3V3_S**→CN3 11/12 跳线→**VCC_3V3**。即三组 "_S / 非_S" 都要靠 CN3 跳线帽连通，不插跳线整板不上电。
- 解析坑：PCB 里 `PAD_NET` 的 header.id 是 **JSON 字符串**（'["PAD_NET","e20","2","e14"]'），要 json.loads 才能拿到 元件id/焊盘号。
